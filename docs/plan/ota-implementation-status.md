# نتائج تنفيذ OTA والنشر والترخيص

تاريخ التحقق: **6 سبتمبر 2026**. نُفّذ العمل محلياً في مساحة Windows بعد موافقة المالك على بدء التنفيذ. **لم يُنشر إصدار، ولم تتغير خصوصية المستودع أو إعداداته على GitHub.** هذه النتائج تخص الشيفرة والحزمة التجريبية في مساحة العمل، ولا تثبت قبول إصدار عام.

اعتمد المالك **AGPL-3.0-only مع خيار ترخيص تجاري منفصل**، بدلاً من سياسة مجانية التعليم فقط. نُسخ النص القياسي كما هو. تستخدم المساهمات Harmony 1.0، الخيار الخامس، وميثاق المجتمع Contributor Covenant 2.1 الرسمي. بُسّط اعتماد النشر إلى مراجعة بيئة GitHub المعتادة ومفتاح التفعيل؛ أُزيلت متغيرات الموافقة القانونية الثلاثة وفحص عبارات المسودة.

## ما نُفّذ

- خدمة تحديث مركزية في Electron، بعقود مشتركة في `packages/contracts` وتحقق التوقيع وسلامة الملفات في `packages/core`. واجهة الإعدادات تعرض التحقق والتنزيل وإعادة التشغيل وقناتي stable وbeta. الفحص الدوري يحترم اختيار المستخدم ويؤخر إعادة المحاولة عند الفشل.
- التحقق من بيان Ed25519 موثوق يربط الإصدار والقناة والمستودع والملفات بأحجامها وبصمات SHA-512. يُفحص الملف بعد التنزيل، ثم مجدداً بعد النسخ الاحتياطي وقبل تشغيل المثبت. لا يُشحن token أو مفتاح خاص داخل التطبيق.
- منع التثبيت أثناء الحصة، وحفظ مسودات المحررات وانتظار العمليات الجارية ومنع الإغلاق أثناء التحضير، ثم إعادة استخدام النسخ الاحتياطي الحالي قبل إغلاق قاعدة البيانات. فشل حفظ صفحة مغلقة يبقى ظاهراً وقابلاً للمعالجة؛ لا تُكتب مسودة قديمة تلقائياً فوق مستند أُعيد فتحه.
- الانتقال من Forge إلى electron-builder، مع staging مستقل عن ملفات التطوير. Windows: NSIS x64؛ macOS: DMG وZIP لكل من x64 وarm64؛ Linux: AppImage x64. هوية المنتج والمستودع والأهداف وأسماء الملفات مركزية في [config.mjs](../../scripts/release/config.mjs).
- أتمتة Release Please لمسودة إصدار مرتبطة بمراجعة محددة، ثم بناء الأهداف الأصلية وفحصها وتجميعها وتوقيع البيان والتحقق من الملفات قبل النشر. تُجمع بيانات تحديث معماريتي macOS دون فقد ملفات أي منهما. يفشل التعارض مع ملف منشور سابقاً؛ لا تستبدل الأتمتة الملفات أو تحذفها.
- إصلاح تعارض نسخة pnpm في CI وتثبيت Actions إلى SHA وصور الأنظمة إلى إصدارات محددة. تستمد CI أهدافها الأربعة من الإعداد المركزي، وتبني وتشغّل الحزمة ببيانات منفصلة على كل هدف. تبقى أسرار التوقيع خارج فحوص المساهمات؛ تُحفظ تشخيصات الفشل دون قواعد البيانات التجريبية.
- صفحة docs `/download` تقرأ أحدث إصدار عام مستقر وتعرض الملفات المكتملة المطابقة للإعداد المركزي. عند غياب الإصدار تعرض حالة صريحة بدلاً من رابط تنزيل مخترع.
- نصوص الترخيص والمساهمة القياسية وشرح عربي وروابط المصدر في التطبيق وبوابة الطالب وصفحة التنزيل. صاحب الحقوق: **CUBETEK ARTIFICIAL INTELLIGENCE - SOLE PROPRIETORSHIP L.L.C.**؛ القانون المختص في نموذج Harmony هو الإمارات. تسمح AGPL بالاستخدام التعليمي وغير التعليمي والتجاري وفق شروطها؛ الترخيص التجاري البديل اختياري. لا تُضاف شروط مخصصة إلى نص AGPL.

سجلات الفحص والملفات المعبأة مخرجات محلية مستثناة من Git، وليست أدلة منشورة أو دائمة. يجب حفظ أدلة قبول الإصدار العام مع مراجعته الفعلية قبل اعتمادها.

أُزيلت مكتبات Sharp الأصلية غير المستخدمة من خادم الطالب، مع بقاء تحسين الصور معطّلاً. قبل إضافة موارد الرخصة الجديدة، انخفض حجم standalone من 79,144,233 إلى 59,397,230 بايت: **19,747,003 بايت، نحو 25%**. نجحت فحوص HTTP بعد الاستبعاد؛ هذا القياس لعزل أثر Sharp، وليس حجم المثبت النهائي.

نصوص الرخصة وإشعارات المكتبات تُولّد من مصدر واحد وتُحمّل عند فتح نافذة «حول البرنامج والرخصة». في الإصدار الرسمي، يرتبط تنزيل المصدر بمراجعة Git المطابقة؛ البناء المحلي المعدّل يعرض رابط المستودع دون الادّعاء أنه يطابق مراجعة نظيفة.

## الحزمة التجريبية

المثبت: `apps/desktop/out-ota-final/CubeCroom-0.1.0-win-x64.exe`، حجمه **124,889,962 بايت**، وبصمة SHA-256:

```text
52218FECF6B245D34CE90471DB6E92D97917AB001BAFB535CD94D0964443ECC5
```

شُغّل التطبيق من `win-unpacked/CubeCroom.exe` بملف مستخدم ومجلد بيانات تجريبيين منفصلين. **لم يُثبّت NSIS، ولم يُختبر انتقال نسخة مثبّتة A→B أو ترحيل Squirrel→NSIS.** لا تُوزّع هذه الحزمة بوصفها إصداراً نهائياً؛ مفاتيح الثقة الإنتاجية لم تُجهّز، لذلك يعرض التحديث حالة غير متاحة.

## المتبقي لتفعيل الإصدار العام

1. تجهيز توقيع Windows وApple Developer ID وnotarization، ومفتاح توقيع بيان الإصدار. `trust.json` يبدأ بلا مفاتيح؛ لم نولّد مفتاح إنتاج أو نفترض توفر شهادات.
2. إتاحة المستودع والمصدر المطابق للإصدار وفق AGPL، واتباع مراجعة المساهمات والإشعارات المعتادة الموضحة في [الترخيص والإصدار](../legal/release-readiness.md). النصوص القانونية معتمدة؛ لا توجد موافقة قانونية مخصصة معلّقة.
3. اختبار تثبيت وتحديث A→B فعلي على Windows x64 وmacOS x64/arm64 وLinux x64، بما يشمل انقطاع التنزيل والحفظ وفشل التوقيع وقاعدة البيانات والمرفقات وإعادة التشغيل. لم تُشغّل macOS أو Linux في هذه الجلسة. اختبار انتقال Squirrel القديم يتطلب نسخة قديمة مثبتة؛ النسخ التي لا تحتوي OTA تحتاج تثبيتاً أولياً يدوياً.
4. إعداد GitHub App وشهادات التوقيع وبيئة `release-publish` بمراجعة GitHub المعتادة، ثم تفعيل النشر. أُزيلت متغيرات الموافقات المخصصة. الأسماء والخطوات في [دليل تشغيل الإصدارات](../../scripts/release/README.md).
5. مراجعة ما سيصبح عاماً قبل تغيير خصوصية المستودع؛ بعدها تفعيل الأتمتة والنشر والتحقق من التنزيل دون حساب. لم يُحدد مضيف نشر docs، لذلك لم تُنشأ عملية نشر لمضيف مفترض.

لا تنفّذ الخدمة تراجعاً آلياً إلى قاعدة بيانات أقدم. الاستعادة تستخدم النسخ الاحتياطية ومسار الاسترجاع الحالي؛ شحن إصدار إصلاحي أحدث يظل مسار معالجة الإصدار المنشور المعيب.
