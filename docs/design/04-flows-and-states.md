# 04 — التدفقات والحالات وتفاصيل الشاشتين الأهم

كل ما في هذا الملف `[مصدر]`.

## 1. التدفق الرئيسي — أول استخدام للمعلم

1. **Welcome**: "أهلاً بك — لن يستغرق الإعداد سوى دقائق."
2. **بيانات المعلم**: الاسم فقط + خيار اسم المؤسسة/المدرسة (اختياري).
3. **مكان البيانات**: افتراضي Recommended مع خيار "تغيير المكان" في Advanced.
4. **AI**: "اربط AI الآن" أو "لاحقاً". **لا تجعل AI شرطاً لتشغيل النظام.**
5. إذا اختار AI: اختيار المزود ← إدخال API Key ← اختبار الاتصال ← اختيار Model افتراضي.
6. إنشاء أول فصل أو الدخول إلى Dashboard.

> الشاشات المقابلة `[استنتاج]`: T02 ← T03 ← (T22/Advanced: مكان البيانات) ← T04 ← T07 أو T05.

## 2. التدفق الرئيسي — بدء حصة ودخول الطلاب

1. المعلم يفتح الفصل ويضغط **"تشغيل دخول الطلاب"**.
2. تظهر شاشة Session مع **QR كبير** + "نسخ الرابط" + حالة الاتصال.
3. الطالب يمسح QR ← Join Page ← الاسم ← "طلب الدخول".
4. المعلم يرى **Toast/Badge "طلب دخول جديد"**.
5. المعلم يضغط "قبول" أو "رفض".
6. الطالب المقبول ينتقل **تلقائياً** إلى الصفحة الرئيسية للفصل.
7. عند انتهاء الحصة يضغط المعلم **"إنهاء دخول الطلاب"** مع Confirmation.

> الشاشات المقابلة `[استنتاج]`: T08 ← T09 ← S01 ← S02 ← T10 ← S04 ← T09 (إنهاء + confirmation).

هذا هو نفس مسار الـ Prototype المطلوب في Deliverables:
`Teacher starts session → Student joins → Teacher approves → Student opens lesson`.

## 3. حالات UI التي يجب تصميمها لكل شاشة

- Default / populated state.
- **Empty state** مع CTA واضح.
- Loading / processing state.
- Success confirmation.
- **Recoverable error** — مع إجراء.
- **Blocking error** — مع تفسير وخطوة لاحقة.
- **Offline / no internet**: لا يؤثر على المحتوى المحلي؛ فقط AI يظهر unavailable.
- **No LAN / student portal unavailable.**
- **Permission denied / session expired** للطالب.
- **Destructive confirmation dialogs.**

> ملاحظة تطبيق `[استنتاج]`: الحالات الأربع الأخيرة سياقية — Offline/AI unavailable تخص T04/T13/T14/T19/S10؛ No LAN تخص T09/T21؛ Permission denied/session expired تخص S02/S03/S04–S10؛ Destructive dialogs تخص حذف فصل، حذف طالب، Restore backup، إنهاء دخول الطلاب، حذف ملف مستخدَم.

## 4. تفاصيل الشاشة الأهم: T09 — Live Access

> هذه هي الشاشة التي تُحوّل Local Hosting إلى تجربة بسيطة للمعلم؛ يجب أن تكون من **أوضح شاشات المنتج**.

- **Header**: اسم الفصل + Badge "دخول الطلاب متاح".
- **Primary zone**: QR كبير في المنتصف/اليمين + رابط مختصر + زر "نسخ الرابط".
- **Live stats**: عدد الطلاب المتصلين + عدد الطلبات بانتظار الموافقة.
- **Requests**: Drawer أو panel جانبي يظهر Pending **فوراً دون تغيير الصفحة**.
- **Connection health**: "جاهز — الطلاب على نفس Wi-Fi يستطيعون الدخول".
- **Primary destructive CTA**: "إنهاء دخول الطلاب" **بلون تحذيري** وConfirmation.
- **Technical details**: hidden accordion يحتوي IP/Port فقط للدعم الفني.

## 5. تفاصيل الشاشة الأهم: T14 — AI Assistant داخل Lesson Editor

> بدلاً من جعل التجربة Chat عامة، التصميم الافتراضي يجب أن يبدأ من **نية المعلم** لأن ذلك أسرع وأوضح لمستخدم غير تقني.

- **Preset actions**: "أنشئ شرحاً"، "بسّط"، "حوّل إلى أسئلة"، "أنشئ ملخصاً"، "اقترح أهداف تعلم".
- **حقل إضافي**: "تعليمات أخرى…" لمن يريد Prompt حر.
- **Display صغير** للمزود/model مع تغيير سريع اختياري.
- **Result يظهر Preview ولا يعدل الدرس تلقائياً.**
- **Actions**: "إدراج"، "استبدال التحديد"، "نسخ"، "إعادة المحاولة".
- **إذا لم يوجد BYOK**: CTA "إعداد الذكاء الاصطناعي" بدل خطأ.
